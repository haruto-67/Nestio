# Nestio 運用ガイド

Pi 上での実際のデプロイ手順。アカウント登録・鍵生成など Claude Code が代行できない作業は
`docs/manual-setup.md` に委ね、ここでは「Docker イメージをビルドしてからサービスとして動かす」
実務的な手順だけをまとめる。

## 前提

- `docs/manual-setup.md` A〜E章の作業（Google OAuth・VAPID鍵・DNS・証明書・.env の値埋め）が
  完了していること
- Pi（Ubuntu, arm64）に Docker Engine / Docker Compose plugin がインストール済みであること

## 1. 初回デプロイ

リポジトリは非公開のため、Pi側にgit認証（デプロイキー等）が無ければ`git clone`できない。
未設定の間は開発機からコミット済みの内容を直接転送する：

```bash
# 開発機側で
git archive HEAD | ssh rpi 'mkdir -p ~/nestio-new && tar -x -C ~/nestio-new'
ssh rpi 'cp ~/nestio/docker/.env ~/nestio-new/docker/.env && rm -rf ~/nestio && mv ~/nestio-new ~/nestio'
```

（Pi側にデプロイキーを登録すれば`git clone`/`git pull`に切り替えられる。未対応）

```bash
cd Nestio/docker
cp .env.example .env
vim .env   # docs/manual-setup.md E章の値を埋める

# named volumeのbind先ディレクトリを先に作っておく
sudo mkdir -p /var/lib/nestio/attachments /var/lib/nestio/logs
sudo chown -R 10001:999 /var/lib/nestio   # コンテナ内のnestioユーザー（uid 10001/gid 999）に合わせる

docker compose build   # 必ずPi上（arm64）でビルドする。better-sqlite3をmacOSでビルドしたバイナリは動かない
docker compose up -d
docker compose ps      # healthy になるまで待つ
curl http://127.0.0.1:3000/api/v1/health
```

マイグレーションはコンテナ起動時（`src/index.ts`）に自動で適用される。手動で流したい場合は：

```bash
docker compose exec nestio node -e "
  const { runMigrations } = require('./dist/db/migrate.js');
  const { createDbConnection } = require('./dist/db/client.js');
  runMigrations(createDbConnection(process.env.DB_PATH));
"
```

## 2. リバースプロキシ（実運用はCaddy）

**実際のPi（`raspiFix`）はnginxではなくCaddyがポート80/443を握っている**
（既存の `niwatorimc.com`（Discord/MCP）サービスと共存させる必要があったため）。
`docker/nginx.conf` は他環境向けの参考として残しているが、このPiでは使わない。
実際に使うのは `docker/Caddyfile.example`。

```bash
# 既存Caddyfileをバックアップしてから追記
sudo cp /etc/caddy/Caddyfile /etc/caddy/Caddyfile.bak-$(date +%Y%m%d%H%M%S)
cat docker/Caddyfile.example | sudo tee -a /etc/caddy/Caddyfile
sudo caddy validate --config /etc/caddy/Caddyfile
sudo systemctl reload caddy
```

DNSが正しくPiを指してさえいれば、Caddyが自動でLet's Encrypt証明書を取得・更新する
（certbot不要）。`sudo journalctl -u caddy -f` で取得状況を確認できる。

添付ファイルはnginxの `X-Accel-Redirect` ではなく、アプリ（`apps/api`）から直接返す方式に
統一済み（Caddyには同等の委譲機構が無いため。`apps/api/src/routes/attachments.ts` 参照）。
このPi以外でnginxを本当に使う場合のみ `docker/nginx.conf` を参照すること。

## 3. ufw の確認

Docker は iptables を直接書き換えるため ufw を貫通しうる。`docker-compose.yml` の
ポート指定が `127.0.0.1:3000:3000` になっていることを必ず確認する（`3000:3000` と書くと危険）。

```bash
sudo ss -tlnp | grep 3000              # 127.0.0.1:3000 になっているか
curl http://<PiのグローバルIP>:3000     # 外部から到達できないことを確認（タイムアウトすればOK）
```

## 4. バックアップ

`docker/backup.sh` を cron に登録する（実行はホスト側。DB・添付は `/var/lib/nestio` に
bindされているため、コンテナに入らず直接読める）。

```bash
sudo cp docker/backup.sh /usr/local/bin/nestio-backup.sh
sudo crontab -e
```

```cron
# 毎日4:00にDBバックアップ、日曜4:30に添付も同期
0 4 * * * NESTIO_RCLONE_REMOTE=dropbox:backup/nestio /usr/local/bin/nestio-backup.sh >> /var/log/nestio-backup.log 2>&1
30 4 * * 0 NESTIO_RCLONE_REMOTE=dropbox:backup/nestio NESTIO_SYNC_ATTACHMENTS=1 /usr/local/bin/nestio-backup.sh >> /var/log/nestio-backup.log 2>&1
```

事前に `rclone config` でリモート（例では `dropbox`）を設定しておくこと。

## 5. アップデート手順

git認証が未設定の間は、1章と同じ`git archive`転送で最新化してからビルドする。

```bash
# 開発機側で
git archive HEAD | ssh rpi 'mkdir -p ~/nestio-new && tar -x -C ~/nestio-new'
ssh rpi 'cp ~/nestio/docker/.env ~/nestio-new/docker/.env && rm -rf ~/nestio && mv ~/nestio-new ~/nestio'

# Pi側で
cd ~/nestio/docker
docker compose build
docker compose up -d
docker compose ps
```

`docker compose down` はしない（named volumeは残るが、無停止更新のほうが安全なため
`up -d` で古いコンテナを入れ替える運用にする）。

## 6. ログの見方・トラブル対応

`docs/manual-setup.md` F章を参照。加えてアプリ内の「サーバーログ」ビューア
（設定 → サーバーログ → 開く）で直近のエラーを時系列・`request_id` 絞り込みで確認できる。

```bash
docker compose logs -f nestio          # 標準出力（起動ログ・未処理例外）
tail -n 200 /var/lib/nestio/logs/nestio-$(date +%F).log | jq 'select(.level>=50)'
```

## 7. GC・保持期間

`apps/api/src/gc/worker.ts` が起動時1回＋24時間ごとに以下を自動実行する。手動操作は不要。

- 30日以上前のtombstone（論理削除行）の物理削除
- 30日以上前の `applied_ops` の削除
- 参照ゼロになった添付ファイル実体の削除
