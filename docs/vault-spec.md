# ナレッジ Vault 仕様（改修25回目）

ナレッジの保存先を SQLite（HTML 本文）から Obsidian 形式の Vault（Markdown ファイル＋フォルダ）へ移す。
**Vault のファイルが唯一の正**であり、ナレッジ本文を DB に保存しない。
背景と判断理由は Nestio のナレッジ「ナレッジのObsidian Vault化」を参照。

## 1. 置き場所

| 項目 | 値 |
|---|---|
| 環境変数 | `VAULT_DIR`（開発時の既定 `./data/vault`） |
| 本番 | `/var/lib/nestio/vault`（既存の bind volume `nestio-data` 配下。ホストから直接見える） |
| ユーザーごとの Vault | `<VAULT_DIR>/<user_id>/`。このディレクトリを Obsidian の Vault として開く |

- rclone マウント等のネットワーク FS 上には置かない（CLAUDE.md「ビルド上の注意」と同じ理由）
- 他端末との同期は未構築（「Vaultの他端末との同期構築」サブタスクで保留中）。
  同期ツールはホスト側で `/var/lib/nestio/vault/<user_id>` を対象にする想定

## 2. フォルダ構成

```
<vault>/
├── _meta/                 # 運用ルール（_記憶規約, _AIのミス記録）
├── profile/               # 本人のこと
├── topics/                # 技術的知見・横断的なトピック
├── projects/
│   └── <プロジェクト名>/
│       ├── <プロジェクト名>.md   # ハブノート（概要・現状・子ノートへのリンクのみ）
│       └── <子ノート>.md         # 主題ごとの子ノート（decision もここ）
├── attachments/           # 画像添付
└── .trash/                # 削除したノートの移動先（Obsidian と同じ）
```

- `people/` は作らない。人物はそれぞれ関係するプロジェクトのフォルダに置く
- ハブノートはフォルダと同名にする。1ノートで済むプロジェクトもフォルダを切る（構成を揃えるため）
- `.` で始まるフォルダ（`.obsidian/` `.trash/` 等）と `attachments/` はナレッジの索引・検索対象外

## 3. ファイル名とタイトル

- **ファイル名（拡張子を除く）＝タイトル**。`[[タイトル]]` は Obsidian と同じくファイル名で解決する
- **ファイル名は Vault 全体で一意**（大文字小文字を区別しない比較で一意。macOS / Windows で衝突しないため）
- タイトルに使えない文字: `\ / : * ? " < > | # ^ [ ]` と制御文字。先頭の `.` も不可
- 子ノートは他プロジェクトと衝突しにくいよう、必要に応じてプロジェクト名を前置する（例:「どこカラ 採点機能」）

## 4. frontmatter

```markdown
---
description: 索引に出る1行要約（必須）
category: project
tags: [nestio, sync]
---
```

| キー | 必須 | 内容 |
|---|---|---|
| `description` | ○ | AI が本文を開くか判断する材料。索引に出る唯一の説明 |
| `category` | ○ | `profile` / `project` / `topic` / `person` / `decision`（現行規約と同じ） |
| `tags` | - | 文字列の配列。フロー形式 `[a, b]` とブロック形式（`- a`）の両方を読める。書き出しはフロー形式 |

- 上記以外のキー（Obsidian 側で追加された `aliases` 等）は読み書きで**保持**する（消さない）
- 値に `:` `#` 等を含む場合はダブルクォートで囲んで書き出す

## 5. 本文

- Markdown（GFM）。HTML へ変換せずそのまま保存する
- リンク: `[[タイトル]]` / `[[タイトル|表示名]]` / `[[タイトル#見出し]]`
- 画像: `![[ファイル名.png]]`（`attachments/` に置く。Obsidian の「添付ファイルの保存先」も `attachments` に設定する）
- 見出し（`#`〜`######`）単位で部分読み取り・部分追記できる

## 6. 書き込みの安全性

「upsert_knowledge(append)の同時書き込みでlost updateが起きる不具合」を Vault で再発させない。

- **version**: ファイル内容の SHA-256 先頭16桁。読み取り時に返し、更新時に受け取る。
  食い違ったら書き込まずエラーを返す（Obsidian・同期ツール・別セッションの変更を無言で上書きしない）
- 書き込みは一時ファイル（同じディレクトリの `.<名前>.tmp-<乱数>`）に書いてから `rename` で置き換える
  （同期ツールが書きかけのファイルを拾わない）
- ファイル操作は同期 API で行い、1リクエスト内の read-modify-write が他リクエストに割り込まれない
  （Node の単一スレッド上で直列化される）
- 削除は `.trash/` への移動（Obsidian と同じ）。同名があれば末尾に時刻を付ける
- パスは必ず Vault ルート配下に正規化して検証する（`..`・絶対パス・シンボリックリンク経由の Vault 外アクセスを拒否）

## 7. 検索・リンク解決

- **ステートレス型**（2026-09-24 ユーザー決定）。検索・バックリンク・索引は毎回ディスクを読む。
  全文検索用 DB もメモリ索引も持たない（件数が数十〜数百の想定で十分速く、同期で書き換えられたファイルともズレない）
- 移動・リネーム時は、そのノートを指す `[[旧タイトル]]`（`|表示名` `#見出し` 付きも含む）を新タイトルへ書き換える

## 8. Web UI・API の扱い（CLAUDE.md「絶対に守ること」2・4 の例外）

ナレッジは Vault が正なので `/sync` の対象外とし、Web UI は専用 API `/api/v1/vault/*` で読み書きする
（2026-09-24 ユーザー承認）。オフラインでは使えない。保存時は version を送り、競合時はエラーを表示する。
タスク・付箋など他の機能は従来どおり IndexedDB＋`/sync` のまま。

## 9. 移行

- 旧 DB の `knowledge` テーブルは「記憶規約の更新と旧ナレッジDBの撤去」サブタスクまで消さない
- 移行は2段階: ①正規化案をユーザーが承認 → ②承認済みの構成で md を生成して Vault に配置
